A new command, `TrackConfig [path]`, saves the current configuration to a file (same as `SaveCfg [path]`) AND launches a process whereby any and all subsequent changes to the configuration are automatically updated (`SaveCfg [path]` executed in the background) -- i.e., a self-updating `SaveCfg`. If user does not supply a path with `TrackConfig`, changes are logged to a file in the directory with `xyscript.exe` (filename to be determined). `TrackConfig STOP` stops configuration tracking.

Related new feature: At startup, XyScript looks for an XPL script named `startup.int` in the directory with `xyscript.exe` and, if present, RUNs it. `startup.int` contains configuration directives that the user wants to implement every time XyScript starts up. This gives the user the option of maintaining continuity of configuration via `RUN my_config_file; TrackConfig my_config_file`. Alternatively, the user could use `startup.int` to implement the same (static) configuration each time XyScript starts up.

If you can think of a better name than `TrackConfig`, please suggest one.
